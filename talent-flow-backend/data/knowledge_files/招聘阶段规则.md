# 招聘阶段规则

本文档定义候选人从简历进入到入职的全流程阶段、流转条件与处理时限，适用于所有社招岗位。

## 一、候选人状态机

系统内候选人状态共 4 种，流转关系如下：

```
pending（待解析） → processing（解析中） → review（待复核） → finish（已确认）
                        ↓                      ↑
                     （解析失败停留）──────────┘
```

### 1.1 状态定义

| 状态 | 含义 | 责任人 |
|------|------|-------|
| pending | 简历已上传，尚未触发智能解析 | HR |
| processing | 系统正在解析简历并生成匹配建议 | 系统 |
| review | 解析完成，等待 HR 逐条复核匹配建议与整体分析 | HR |
| finish | HR 已确认复核结果，进入后续面试安排 | HR |

### 1.2 关键规则

- **解析失败不设独立状态**：解析失败的候选人停留在 review，失败原因记录在简历信息字段中，由 HR 人工补全
- **finish 为终态保护**：已确认候选人参与要求变更重算时保持 finish 状态，不回退到 review
- **僵死自愈**：processing 状态超过 3 分钟未更新视为后台任务丢失，允许重新触发解析
- **并发去重**：同一候选人同时只允许一个解析任务执行，重复触发将被跳过并提示

## 二、各阶段处理时限

| 环节 | 时限 | 超时处理 |
|------|------|---------|
| 简历解析 | 提交后 3 分钟内完成 | 超时判定僵死，可手动重试 |
| HR 复核 | 解析完成后 2 个工作日内 | 超过 5 个工作日未复核由招聘负责人提醒 |
| 面试反馈 | 面试结束后 24 小时内 | 超时由面试官直属上级催办 |
| offer 审批 | 面试通过后 3 个工作日内 | 超时升级至部门负责人 |

## 三、简历查重与合并

- 系统按简历文件内容哈希查重，命中重复时返回已存在候选人，不重复入库
- 同一人不同渠道投递的简历，人工确认为同一人后合并，保留最新简历，历史记录关联至主档
- 删除候选人将级联删除其简历、匹配建议与打分记录，操作不可恢复，需二次确认

## 四、职位要求变更的重算规则

职位要求项变更（新增、修改、删除）后可触发该职位下已解析候选人的批量重算：

1. 重算重新执行简历解析并覆盖重建匹配建议
2. 已确认（finish）候选人保持 finish，其余回退到 review 等待复核
3. 正在解析中的候选人本轮跳过，不参与重算，也不计入失败
4. 重算完成后自动按当前算法参数重算匹配得分

## 五、异常与人工介入

| 场景 | 处理方式 |
|------|---------|
| LLM 解析两次重试后仍失败 | 转人工复核，HR 手动补全基本信息与匹配建议 |
| 知识库检索服务不可用 | 自动降级为纯 LLM 生成，结果标注低置信，不阻断流程 |
| 职位无要求项 | 解析时自动从 JD 提取要求项并落库；JD 也为空时要求项为空，匹配建议仅含基本信息 |
| OCR 识别失败 | 图片类简历静默降级，按已抽取文本解析，缺失信息由 HR 复核补齐 |
