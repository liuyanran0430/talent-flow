# 岗位能力标准手册

本手册定义公司在技术招聘中通用的岗位能力标准，作为简历筛选、面试评价与入职定级的统一依据。所有标准条目以知识库（kb_standards）中已发布版本为准，本文件为其说明性补充。

## 一、标准的结构与命名

每条能力标准包含以下要素：

- **名称**：简洁可辨识的技能或素质名称，如「RAG 原理」「Python 开发经验」
- **判定标准**：达到该标准的具体行为或成果描述
- **证据要求**：候选人应在简历或面试中提供的支撑材料类型
- **重要度**：高 / 中 / 低，用于打分权重
- **类型**：必须 / 加分，必须项不满足即不予通过

## 二、技术能力标准（工程方向）

### 2.1 编程语言

| 标准 | 判定标准 | 证据要求 | 重要度 |
|------|---------|---------|-------|
| Python 开发经验 | 具备 3 年以上 Python 项目开发经验，熟悉面向对象设计与工程化实践（虚拟环境、类型注解、单元测试、代码评审） | 简历需包含具体项目案例、技术栈与承担角色 | 高 |
| Go 开发经验 | 熟悉 Go 并发模型（goroutine/channel），有高并发服务开发经验 | 简历需体现服务性能指标或压测数据 | 中 |
| SQL 与数据库 | 能独立完成复杂查询、索引设计与慢查询优化 | 简历需体现具体优化案例与效果数据 | 中 |

### 2.2 大模型应用

| 标准 | 判定标准 | 证据要求 | 重要度 |
|------|---------|---------|-------|
| RAG 原理 | 理解检索增强生成的完整链路（文档切块、向量化、召回、重排、生成），能独立定位召回质量问题的环节 | 简历需体现 RAG 项目的知识库规模、命中率或延迟指标 | 高 |
| 大模型微调 | 熟悉 LoRA/QLoRA 等参数高效微调方法，了解显存优化技术（ZeRO、FlashAttention） | 简历需体现微调过的模型规模与训练配置 | 中 |
| Agent 项目经验 | 有独立或团队协作的 Agent 编排开发经历，理解工具调用、规划与记忆机制 | 简历需体现所用框架（LangGraph、AutoGen 等）与业务场景 | 中 |
| Prompt 工程 | 能系统化设计提示词，理解 few-shot、思维链、结构化输出约束 | 简历需体现提示词迭代优化的实际案例 | 中 |

### 2.3 工程素养

| 标准 | 判定标准 | 证据要求 | 重要度 |
|------|---------|---------|-------|
| 系统设计能力 | 能对中等复杂度系统做模块划分、接口设计与容量估算 | 面试中白板设计环节表现 | 高 |
| 问题排查能力 | 能通过日志、监控、复现等手段定位线上问题根因 | 简历或面试中描述完整排障案例 | 高 |
| 代码质量意识 | 有代码评审、重构、技术债务管理经验 | 简历需体现评审参与度或重构成果 | 中 |

## 三、通用素质标准

### 3.1 沟通协作

- **判定标准**：能清晰表达技术方案，主动同步进展与风险，在跨团队协作中推动问题闭环
- **证据要求**：面试官行为面试环节记录的具体事例

### 3.2 学习能力

- **判定标准**：近一年内有主动学习并落地新技术的经历
- **证据要求**：简历中体现的新技术应用项目，或面试中对技术原理的追问回答深度

### 3.3 业务理解

- **判定标准**：能解释所参与项目的业务目标，理解技术方案的业务代价
- **证据要求**：面试中对「为什么做」「效果如何衡量」的回答

## 四、职级差异说明

同一能力标准在不同职级的期望深度不同：

| 职级 | 期望 |
|------|------|
| 初级（P5 及以下） | 能在指导下完成任务，掌握基础知识 |
| 中级（P6） | 独立负责模块，能识别并解决常见问题 |
| 高级（P7） | 主导系统设计，能指导他人，处理复杂场景 |
| 专家（P8 及以上） | 定义技术方向，跨团队影响力，体系化建设 |

## 五、标准的使用与更新

1. 简历匹配时，要求项优先关联已发布标准；标准缺失时按 JD 原文判定并在评审中标注
2. 标准条目由岗位负责人提出，经招聘委员会评审后发布
3. 标准条目内容变更后自动失效旧向量索引，历史匹配结果不重算，新解析按新标准执行
